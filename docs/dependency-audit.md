# Dependency audit: accepted risks

Last reviewed: 2026-10-26 (session M). `pnpm audit --prod` is clean. The advisories below are the only ones `pnpm audit` (dev dependencies included) still reports.
Whoever owns the next SvelteKit upgrade session decides when to revisit them; all three go away with SvelteKit 3.

| Advisory            | Package (installed)                  | Severity | Why it is not fixed                                                                                                        | Why it is not reachable                                                                                                                                                                                                                                                                       |
| ------------------- | ------------------------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GHSA-27mw-82g8-phjj | `@sveltejs/kit` 2.70.3               | low      | Fixed only in 3.0.0 (a major bump).                                                                                        | XSS needs a prerendered page whose `cache-control` comes from `setHeaders` with untrusted input. MIRA prerenders nothing (no `prerender` export or config), and every `setHeaders` call uses a constant or a computed integer (`retry-after`, `www-authenticate`, `cache-control: no-store`). |
| GHSA-pfhg-q3qv-9q6r | `@sveltejs/kit` 2.70.3               | low      | Fixed only in 3.0.0.                                                                                                       | Open redirect needs `use:enhance` on a route that accepts paths starting with `//`, such as a catch-all route. MIRA has no catch-all route; `use:enhance` appears only in `account/tokens` and `PipelineSteps.svelte`.                                                                        |
| GHSA-pxg6-pf52-xh8x | `cookie` 0.6.0 (via `@sveltejs/kit`) | low      | Kit 2.x depends on `cookie@^0.6.0`; kit 3 moves to cookie 2. An override to 2.x would cross a major that kit 2 cannot use. | The flaw is in `serialize()` with attacker-controlled cookie name, path or domain. MIRA never calls `event.cookies.set`; cookies are set by better-auth, which has its own cookie code, with fixed names.                                                                                     |

## Why SvelteKit 3 was not taken in this session

3.0.0 is a large major release: `$lib` becomes `#lib`, `cookie` v2 (ASCII names, default `path: '/'`), the adapter-node `ORIGIN` environment variable is removed in favour of `kit.paths.origin` (a deployment change for the Helm chart), external redirects are forbidden by default, form action status codes change, `handleError` runs for all errors, and `@sveltejs/adapter-node` 6 is required. That is a dedicated migration, not a security patch, and the three advisories above are low severity and unreachable. Revisit by 2027-01-31, or sooner if a reachable SvelteKit advisory appears.
